# 04 · 黑盒测试方案

> 前提：拥有 **真实账户** 与 **模拟盘（paperMoney）账户** 各一。
> 原则：**测试流量默认打模拟盘；真实账户只允许只读探测；任何写操作有硬闸门。**
> 停更一年后线上（服务器 build 已到 27.2640.4）的每个服务都要先"普查"再回归。

## 1. 测试分层

```
L0 匿名探针      无凭据        握手/心跳/帧格式/版本号        随时可跑（CI 可选）
L1 认证生命周期  需凭据        登录/token 过期/refresh/MFA    低频（token 宝贵）
L2 只读服务普查  模拟盘        全部读服务的请求-响应录制      每日/改版后
L3 写操作验证    仅模拟盘      下单/改单/撤单/告警增删        手动触发
L4 真实账户冒烟  真实账户      仅只读子集（quotes/positions） 极低频、只读白名单
L5 长稳与重连    模拟盘        24h+ 挂连、断网恢复、内存      夜间任务
```

## 2. 目录与工具（agent/tools/ 已起步）

```
agent/tools/
├── probe-ws.mjs          # ✅ 已建：L0 匿名握手探针（实测记录在 00）
├── .env.blackbox         # 本地凭据（gitignore：模拟盘+真实账户 token/账密分开）
├── record.mjs            # L2/L3 录制器：跑一个服务 → 原始帧逐条落盘
│                         #   agent/artifacts/<date>/<service>.jsonl（snapshot+patch 原样）
├── probe-services.mjs    # L2 普查 runner：读服务清单 → 依次请求 → 断言 + 录制 + 报表
├── auth.mjs              # L1：半人工登录取 authCode（浏览器打开、人完成 MFA、截 code）、
│                         #      token 换发、refresh 通道探测、剩余有效期推断
├── drift.mjs             # X4 协议漂移对比：今天的录制 vs 基线录制的 schema diff
└── safety.mjs            # L3/L4 闸门（见 §6）
```

`.env.blackbox` 建议字段：

```
TOS_PAPER_ACCESS_TOKEN / TOS_PAPER_REFRESH_TOKEN
TOS_REAL_ACCESS_TOKEN / TOS_REAL_REFRESH_TOKEN   # 只读冒烟用
TOS_PAPER_ACCOUNT / TOS_REAL_ACCOUNT             # 账户号（正则脱敏后入日志）
```

## 3. L2 只读服务普查矩阵（首轮手工核对，之后自动化）

每个服务记录：请求原文、首个 snapshot、3+ 个 patch、字段清单、耗时；
输出对比表：字段增删 / 类型变化 / 新增枚举值（与仓库内既有类型定义 diff）。

| 服务                | 用例                    | 通过判据                                       |
| ------------------- | ----------------------- | ---------------------------------------------- |
| quotes              | AAPL,SPY + 盘外时段     | snapshot 含 items[].values 14 字段，patch 持续 |
| chart               | DAY/YEAR2 + MIN/1D 各一 | candles 六数组等长、时间戳单调                 |
| positions           | 模拟盘账户              | items 结构含 instrument/values                 |
| user_properties     | —                       | defaultAccountCode 存在                        |
| order_events        | types:["WORKING"]       | snapshot 可达，空账户也应有空 items            |
| instrument_search   | "TSLA", "100"           | instruments[] 非空                             |
| optionSeries        | AAPL                    | series[] 非空，expiration 可解析               |
| optionSeries/quotes | AAPL                    | IMPLIED_VOLATILITY 数值                        |
| option_chain/get    | AAPL+seriesNames        | optionPairs strike 升序                        |
| quotes/options      | AAPL 窄 strike 区间     | BID/ASK/DELTA 字段                             |
| market_depth        | SPY                     | bid/askQuotes patch 按 index 合并正确          |
| watchlist/get       | 已知 id                 | watchlist.symbols                              |
| alerts/lookup       | —                       | alerts[]                                       |
| 错误路径            | 非法 symbol / 非法账户  | 收到 type:"error"（验证 P2 行为）              |

⚠️ 顺序注意：同一连接上并发订阅会互相污染（P1），普查 runner **一次只开一个订阅、
收满即 unsubscribe（换新 id 重发空集）或断开重连**。

## 6. 安全闸门（safety.mjs 强制，写进代码而非文档）

1. 环境变量 `TOS_ENV=paper|real`，**只有 paper 才允许** place/replace/cancel/alert 写服务；
   real 环境调用写服务直接 throw。
2. real 环境白名单：quotes / chart / positions / user_properties / order_events /
   instrument_search / option\* / watchlist/get / alerts/lookup。
3. 下单参数硬限制：数量 ≤ 1、限价 ≤ $5、仅限白名单标的（AAPL/SPY 类低价票）、
   每日模拟盘下单次数上限（如 20）。
4. 日志脱敏：token/authCode/账户号一律正则打码后才允许落盘（录制文件同理）。
5. artifacts 目录与 `.env.blackbox` 进 `.gitignore`。

## 7. 协议漂移监测（长期）

- 每次普查产出 `schema digest`（每个服务的字段名集合 + 类型），与基线 diff → 报告
  "新增/删除/类型变化" 三类差异。
- 服务器 `build` 号入报表头；build 变化即触发全量 L2 复跑。
- 目标：线上改协议后 **1 天内**由测试矩阵首先发现，而不是实盘业务发现。

## 8. 执行顺序建议

1. 先跑 L0（已通过）→ auth.mjs（C1/C2，拿到模拟盘 token）
2. L2 全量普查 + 录制基线 → 更新类型定义
3. C3/C4/C5（认证生命周期）→ 决定 token 管理设计
4. W1-W7 写路径验证 → 交易接口定稿
5. L5 长稳 → 重连/心跳看门狗验收
6. 最后才允许 L4 真实账户只读冒烟
