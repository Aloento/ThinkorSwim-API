# 07 · 集成设计：WsJsonClient 门面方法（task-3 依据）

> 前提：task-1（id 路由/错误帧）与 task-2/4（服务 handler）完成后执行。
> 原则：门面方法一律用黑盒实测确认的 handler 与参数名；Promise 型取首个
> snapshot；需要持续推送的用 AsyncIterable。

## 现状缺口

`wsJsonClient.ts` 门面已有 19 个方法，但登录链路（schwabLogin 旧协议）与
2026-10 线上不符；已实测的 15+ 服务没有对应方法。

## 下单草稿 id 规则（关键，勿改）

```
CONFIRM 与 SUBMIT 必须复用同一 header.id（草稿态由服务端按 service+id 保存）。
换 id 提交 = "Can not submit while prices are not available!"。
orderId 从 SUBMIT 后的 patch /orders/0/orderId 读取（task-1 合并 patch 后即可见）。
```
