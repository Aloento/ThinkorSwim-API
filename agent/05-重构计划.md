# 05 · 重构与现代化计划

> 输入：01（结构）、02（协议）、03（风险 R/P/T/A/S/E/X 编号）、04（黑盒方案）。
> 约束：**渐进式重构**，保持 `WsJsonClient` 门面基本兼容；每个阶段有独立验收，
> 小步提交；黑盒测试先于盲改——**凡是未录制确认的字段，不猜测修改**。

## 阶段 0 · 止血与地基（不动业务代码，1~2 天）

目标：仓库干净、验证闭环建立。

- [ ] `.gitignore` 增加 `.env*`（保留示例模板）、`agent/artifacts/`、`puppeteer-data/`；
      从仓库删除 `cert.pem`/`key.pem`（E3），删除空的 `orderEventTypes.ts`（E4）。
- [ ] 修 `package.json`：删除不存在的 `main/types` 指向（改 `exports` 单轨）、
      删除失效 `bundle` 脚本或改指真实入口（E1）；`puppeteer`+`prompts`+`resolve` 移到
      `devDependencies` 或拆 `examples/` 独立包（E2）；`lodash-es` 用一处 `isString`
      改原生判断后移除依赖。
- [ ] 建立黑盒工具骨架：`agent/tools/{auth,record,probe-services,safety}.mjs` + `.env.blackbox.example`（按 04 §2、§6）。
- [ ] CI 增加 `tsc --noEmit` 快速作业；保留现有四连（prettier/build/lint/test）。

验收：`yarn ci` 绿；`node agent/tools/probe-ws.mjs` 仍过；`.env.blackbox` 就位。

## 阶段 1 · 认证与连接生命周期现代化（R1-R6，最高优先）

- [ ] **认证器抽象** `Authenticator`：持有 accessToken/refreshToken + 获取时间戳；
      实现 `getValidToken()`——到期前（23h 阈值）或收到鉴权错误时自动刷新。
      刷新通道以黑盒 C3 的结论实现（优先探 OAuth HTTP 端点 `grant_type=refresh_token`，
      备选重放 `login/schwab`）。
- [ ] **半人工登录**替换脆弱 puppeteer 自动填表（C1）：浏览器只负责让人完成
      登录+MFA，工具只截 `oauth?code=`；保留 stealth 但去掉 DOM 选择器依赖；
      加超时/用户中断路径。
- [ ] **连接生命周期重写**（R2/R3/R4）：
  - WebSocket 工厂化，close/error → 状态机回落 → 指数退避重连（0.5s→30s，可配）；
  - 重连成功后自动重新 login + **重放活跃订阅**（记录每个 dispatch 的请求原文）；
  - 握手/登录加超时；`onclose` 正确落状态；ERROR 可通过 reconnect 恢复；
  - 心跳看门狗（>10s 未收到 heartbeat 判定死链主动重连，参数由 C5 实测定）。
- [ ] 错误对象化：reject Error 子类（AuthError/ProtocolError/TransportError），
      替换字符串 reject（R6）。

验收：模拟盘 24h 挂连不断（L5）；拔网线 30s 自动恢复并续收 quotes；
token 跨 24h 自动续期成功。

## 阶段 2 · 协议层正确性（P1-P7，交易安全的前提）

- [ ] **请求-响应按 id 关联**（P1/P6）：请求 id 改为 `randomUUID()`；
      分发路由 `service+id`；保留"按 service 订阅型"与"按 id 请求型"两种语义。
      ——这同时根治 T1（placeOrder 的 promise 永不 resolve）。
- [ ] **错误帧一等公民**（P2）：`type:"error"` → 推入对应流的 error 通道 /
      reject promise；不再 console.warn 吞掉。
- [ ] patch 缺基底保护（P3）：缺 snapshot 时请求重发或显式报错；`dataStore` 加
      LRU 上限或随订阅生命周期清理（P4）。
- [ ] 消息循环加 try/catch 隔离畸形帧（P5）；空 payload 防御。
- [ ] 可配置项下沉：quotes 的 account、chart id 前缀、User-Agent 头等（P7）。
- [ ] 录制回放单测：把 L2 录制的真实帧做成 jest fixture，
      snapshot/patch 合并、错误帧、乱序 patch 全走回放测试（E6 补债）。

验收：并发两个不同 symbols 的 quotes 互不串台；错误帧可使 promise reject；
回放测试覆盖全部 19 个服务。

## 阶段 3 · 交易 API 加固（T1-T5，接真实资金前必须完成）

- [ ] 下单流重做：CONFIRM → 校验确认（价格区间/成本/保证金字段）→ SUBMIT →
      以 id 关联等待受理，返回结构化 `OrderResult{orderId, refOrderId, status}`；
      任一环节失败即终止并抛错（T2）。
- [ ] 订单类型扩展：market/limit、tif 可选、卖出数量语义显式化（side 字段而非
      正负数量）、期权单（INIT_OPTION）与多腿结构留接口（T3）；
      改单响应确认语义（T4）。
- [ ] `orderEvents()` 一等公民流：按账户订阅，映射 `RawOrderEvent` → 归一化事件
      （状态机：ACCEPTED/PARTIAL/FILLED/CANCELED/REJECTED）。
- [ ] **安全闸门进库**（非仅测试工具）：可选 `guard` 配置（账户白名单、数量/金额
      上限、paper-only 模式），默认保守。

验收：模拟盘 W1-W7 全绿；断网/竞态下无"双提交"；回放测试覆盖确认失败路径。

## 阶段 4 · 类型与 API 打磨（A1-A7）

- [ ] 每个服务定义响应类型并用 zod（或 io-ts）在边界解析，`ParsedPayloadResponse`
      泛型化为 `ServiceResponse<S>`；保留 `rawBody` 逃生舱（A1/A2）。
- [ ] `WsJsonClient` 接口整理：补 `connect()`/`reconnect()`/`refreshToken()`；
      错误语义文档化（A7）；`subscribeToAlerts` 接入或删除（A4）。
- [ ] 代理协议 v2：明确 `args` 规则（一律数组）、错误响应 `{error:{code,message}}`
      （S2/S3）、可选共享 secret 鉴权（S1）；`ALL_REQUESTS` 去重（A6）。
- [ ] README 重写（中文为主）：认证流程图、服务矩阵、安全免责声明、修包名拼错。

## 里程碑顺序与依赖

```
阶段0 ──▶ 阶段1 ──▶ 阶段2 ──▶ 阶段3 ──▶ 阶段4 ──▶ 阶段5
             ▲          │
             └── 黑盒 C/W 组测试结论反哺设计（04 §8）
```

核心原则回顾：

1. **测试先行**：线上行为以录制为准，不凭旧代码记忆改协议。
2. **交易保守**：写路径的一切改动先在模拟盘验证。
3. **小步可回滚**：每阶段独立可发布，接口保持向后兼容。
